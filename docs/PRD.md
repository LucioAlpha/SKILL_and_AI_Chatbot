## 2. 背景與目標（Background & Objectives）

### 問題陳述

台灣民眾有前往廟宇求籤問卜的傳統文化習慣，但受限於時間、地點與交通，許多人無法親自到廟宇求籤。同時，現有的線上占卜類服務缺乏正統廟宇氛圍，無法給予使用者身歷其境的儀式感與文化認同感。

### 產品目標

打造一個具備台灣公廟文化氛圍的線上抽籤體驗網站，讓用戶在任何時間、任何地點，都能以虛擬方式完成「搖籤筒 → 抽籤 → 解籤」的完整儀式，獲得心靈指引與運勢參考。

### 成功指標（KPI / OKR）

- **月活躍用戶（MAU）**：上線 3 個月內達到 5,000 人
- **單次抽籤完成率**：> 85%（用戶完成搖籤到查看籤詩全流程）
- **平均頁面停留時間**：> 90 秒
- **社群分享率**：每日抽籤用戶中，> 10% 分享籤詩至社群媒體
- **回訪率（7 日）**：> 30%

## 3. 目標用戶（Target Users）

### 用戶角色（Personas）

| Persona | 描述 |
|---------|------|
| **信仰實踐者** | 30–60 歲，習慣於廟宇求籤，因時間/身體不便轉而使用線上服務 |
| **文化好奇者** | 18–35 歲，對台灣民俗文化感興趣，想體驗抽籤但沒有廟宇經驗 |
| **心靈探索者** | 各年齡層，在人生重要決策（婚姻、工作、健康）前尋求指引 |
| **外國訪客** | 旅遊台灣的外籍人士，對台灣廟宇文化感到好奇 |

### 用戶痛點（Pain Points）

- 廟宇求籤需親自前往，受限於距離與開放時間
- 不熟悉求籤禮儀，擔心行為不當冒犯神明
- 籤詩文字為文言文，難以自行理解
- 現有線上占卜服務界面粗糙，缺乏廟宇的儀式感與可信度

### 使用情境（Use Cases / Scenarios）

1. 用戶在深夜煩惱工作問題，無法前往廟宇，開啟網站虛擬求籤獲得心靈慰藉
2. 用戶在重要面試前，想抽一支籤鼓勵自己，分享籤詩至 LINE 群組
3. 外籍旅客在台灣廟宇參觀後，想進一步了解籤詩文化，使用英文介面體驗

## 4. 功能需求（Functional Requirements）

### 使用者故事（User Stories）

| # | 使用者故事 |
|---|-----------|
| US-01 | As a **信仰實踐者**, I want to **選擇求籤的類別（感情、事業、健康、財運）**, so that **我能獲得針對我問題的籤詩指引** |
| US-02 | As a **文化好奇者**, I want to **觀看搖籤筒的動畫效果**, so that **我能感受到接近廟宇現場的儀式感** |
| US-03 | As a **心靈探索者**, I want to **看到籤詩的白話文解釋**, so that **我能理解籤詩對我問題的建議** |
| US-04 | As a **任意用戶**, I want to **將抽到的籤詩分享至社群媒體**, so that **我可以與朋友分享運勢** |
| US-05 | As a **外國訪客**, I want to **切換語言至英文**, so that **我能理解籤詩內容** |
| US-06 | As a **任意用戶**, I want to **查看歷史抽籤紀錄**, so that **我能回顧過去的運勢指引** |

### 功能清單與驗收標準

#### F-01：求籤類別選擇

**描述**：用戶進入網站後，可選擇欲問事項的類別。

**驗收標準（AC）**：
- [ ] 首頁顯示至少 4 個類別（感情、事業、健康、財運）
- [ ] 每個類別有對應的圖示與說明文字
- [ ] 選擇類別後，跳轉至搖籤畫面
- [ ] 類別選擇頁面載入時間 < 2 秒

#### F-02：虛擬搖籤動畫

**描述**：模擬廟宇中搖動籤筒的互動動畫體驗。

**驗收標準（AC）**：
- [ ] 顯示擬真的籤筒 3D/2D 動畫
- [ ] 用戶點擊「搖籤」按鈕後，動畫持續 2–4 秒
- [ ] 動畫包含聲音效果（可選擇靜音）
- [ ] 搖籤動畫在手機瀏覽器上正常顯示

#### F-03：籤詩顯示

**描述**：抽籤後顯示完整的籤詩內容，包含籤號、籤詩原文及解釋。

**驗收標準（AC）**：
- [ ] 顯示籤號（如：第三十六籤）與籤詩等級（上上、上、中、下、下下）
- [ ] 顯示籤詩原文（文言文）
- [ ] 顯示白話文解釋，針對用戶選擇的問事類別給出解析
- [ ] 籤詩圖片設計具備廟宇傳統美感（紅底金字風格）
- [ ] 系統包含至少 60 支籤（上上籤至下下籤均勻分布）

#### F-04：籤詩分享

**描述**：允許用戶將籤詩以圖片或文字形式分享至社群媒體。

**驗收標準（AC）**：
- [ ] 提供「分享至 LINE」、「分享至 Facebook」、「複製連結」三種方式
- [ ] 分享內容包含籤號、籤詩摘要與網站連結
- [ ] 分享功能在手機與桌面瀏覽器均可正常使用

#### F-05：多語言支援

**描述**：提供繁體中文與英文介面切換。

**驗收標準（AC）**：
- [ ] 頁面右上角提供語言切換按鈕（中 / EN）
- [ ] 切換語言後，所有頁面文字即時更新，無需重新載入
- [ ] 英文版籤詩解釋內容與中文版對應

#### F-06：抽籤紀錄

**描述**：在本機儲存用戶的抽籤歷史，方便回顧。

**驗收標準（AC）**：
- [ ] 使用 localStorage 儲存最近 10 筆抽籤紀錄
- [ ] 每筆紀錄包含：抽籤時間、類別、籤號、籤詩摘要
- [ ] 用戶可清除所有歷史紀錄

## 5. 非功能性需求（Non-Functional Requirements）

| 面向 | 需求 |
|------|------|
| **效能** | 首頁 LCP（Largest Contentful Paint）< 2.5 秒；搖籤動畫幀率 ≥ 30 FPS |
| **安全性** | 無需用戶登入，不蒐集個人資料；若加入後台，管理頁需 HTTPS + 身份驗證 |
| **可靠性** | 純前端靜態網站，目標可用性 99.9%；部署於 CDN（如 GitHub Pages / Vercel） |
| **可擴展性** | 籤詩資料以 JSON 格式儲存，便於新增廟宇資料或擴充籤詩數量 |
| **相容性** | 支援 Chrome、Safari、Firefox、Edge 最新兩版；支援 iOS 15+ 及 Android 10+ 行動裝置 |
| **無障礙性** | 符合 WCAG 2.1 AA 標準；所有圖示提供 alt text |

## 6. UX / UI 需求

### 整體風格

- **視覺主題**：台灣傳統廟宇風格，以紅色、金色、深棕色為主色調
- **字型**：標題使用毛筆風格字體（如 Noto Serif TC）；內文使用易讀的無襯線字體
- **氛圍**：透過背景音效（廟宇鐘聲、香煙縈繞動畫）營造儀式感

### 使用者流程（User Flow）

```
[首頁 - 廟宇場景]
       ↓ 點擊「開始求籤」
[選擇問事類別]
       ↓ 選擇類別
[輸入心中所求（可選）]
       ↓ 點擊「搖籤」
[搖籤動畫（2-4秒）]
       ↓ 動畫結束
[籤詩結果頁]
       ↓ 查看詳細解析 / 分享 / 再抽一次
```

### 關鍵互動行為

- **搖籤互動**：支援點擊或晃動手機（Device Motion API）觸發搖籤
- **籤詩揭示**：籤詩以翻轉卡片動畫方式揭曉（增加儀式感）
- **錯誤處理**：若瀏覽器不支援某功能，顯示友善提示而非錯誤頁面

---

## 7. 系統與技術限制（Constraints & Dependencies）

- **技術架構**：純前端靜態網站（HTML + CSS + JavaScript），無需後端伺服器
- **資料儲存**：籤詩資料儲存於 JSON 檔案；抽籤紀錄儲存於 `localStorage`
- **第三方服務**：
  - 社群分享：LINE Share API、Facebook Share API
  - 部署：GitHub Pages 或 Vercel（免費方案）
- **授權**：籤詩內容需確認版權，建議使用公開領域的傳統籤詩

## 9. 範圍外（Out of Scope）

以下功能**不包含**在 v1.0 版本中：

- ❌ 用戶帳號系統與雲端同步紀錄
- ❌ 付費功能（進階解籤、VIP 解析）
- ❌ 即時與廟方互動（如線上問事）
- ❌ 多廟宇資料庫整合
- ❌ 行動 App（iOS / Android 原生應用）
- ❌ 後台管理系統（籤詩內容管理）
- ❌ 廣告投放系統
